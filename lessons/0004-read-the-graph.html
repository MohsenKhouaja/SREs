Executable policy

Edges say what is allowed next

START ─┬─ log ─────┐ ├─ metrics ──┼─ correlation → approval → record_decision └─ event ────┘ ├ approved → execute → report → END └ rejected → rejected_report → END

Three START edges fan out. The edge from [log, metrics, event] is a join: Correlation waits for every collector. The conditional edge reads approval_result; only one value can reach execute.

Invocation

The graph runs inside a tracked async task

start() stores an asyncio.Task by Investigation ID. _run_initial() waits for telemetry warm-up, constructs every required state field, and calls graph.ainvoke with a 300-second outer timeout. If the result contains an interrupt, it publishes approval_required.

thread_id = investigation_id connects all checkpoint operations for one Investigation. Resume later calls the same graph with Command(resume=approved) and the same configuration.

Failure semantics

RetryPolicy covers thrown collector failures

The three collector nodes have up to three attempts, initially spaced by half a second. Correlation and later nodes do not use that policy. More importantly, Loki and Prometheus tools catch their own exceptions and return error envelopes, so those ordinary network failures do not escape the node and therefore do not trigger graph retry.

Interview distinction: graph topology handles orchestration; node and tool code still determine what counts as failure. A retry policy cannot retry an error that has been converted into normal data.

Teach it back

Describe the graph without using the words LangGraph, node, or edge.

Model answer
The system starts three evidence collectors concurrently, waits until all have finished, combines their results, pauses for a human decision, records that decision, and then either performs recovery before reporting or reports rejection without recovery.
