Four layers

A metric does not enter state directly

  1. Scenario profile selects a query

    For bad deployment: HTTP 500 ratio in PromQL and v2/error patterns in LogQL.

  2. Tool calls an observability HTTP API

    Prometheus uses /api/v1/query_range; Loki uses /loki/api/v1/query_range.

  3. Tool returns a uniform envelope

    status, data, and metadata preserve values, source, query, duration, or error.

  4. Collector wraps it as a Finding

    Timestamp, source, profile-written message, and the entire tool response as raw_data.

Why @tool?

The wrapper standardizes invocation and metadata

The workflow calls query_loki.invoke({...}) and query_prometheus.invoke({...}). These functions are synchronous, so async collector nodes move them to a worker thread with asyncio.to_thread; otherwise blocking HTTP would stall the event loop.

Time strings such as now-5m are parsed locally. Loki receives nanoseconds; Prometheus receives seconds and a five-second query step.

Read call sites

The catalog is larger than the executed workflow

AGENT_TOOLS advertises health, time, stacktrace, error-pattern, rate, period-comparison, event-correlation, and formatting capabilities. But the current graph directly invokes only Loki query, Prometheus query, timeline building, hypothesis ranking, root-cause synthesis, and report formatting. There is no model-driven loop selecting freely from AGENT_TOOLS.

Grounding limitation

An error can still become a confidently worded Finding

Query tools return {status: "error", ...} rather than throwing. The collector nevertheless attaches the scenario profile’s expected message. Correlation can continue using that message and error-shaped raw data. This makes the demo reproducible, but it weakens the claim that every conclusion is proven by live telemetry.

Production improvement

Validate successful, non-empty tool evidence before emitting a positive Finding; otherwise mark the source unavailable and reduce confidence or stop for operator review.

What normally happens when Loki is unavailable?

Teach it back

For one Log Finding, name the query origin, HTTP call, envelope, state representation, and grounding weakness.

Model answer
The Scenario profile supplies LogQL. query_loki converts the range and calls Loki, returning a success/error envelope. The Log Agent stores that envelope in a Finding’s raw_data beside a profile-authored message. Because errors are data and the message is predetermined, the message can sound conclusive even when Loki failed.
