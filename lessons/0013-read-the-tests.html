Shortest system specification

The rejection test captures the central safety promise

It creates InMemoryStore/EventHub/Workflow, starts bad deployment with zero warm-up, waits for the initial task, and asserts four collectors completed while Report waits. It verifies one pending Approval with all Evidence groups, resumes false, and checks completed_with_rejection, a root cause, and rejected Approval.

Because observability tool failures return data, the workflow can complete without Loki or Prometheus. That makes the test deterministic but means it does not prove real evidence integration.

Isolation

Tests replace infrastructure at composition boundaries

API tests inject Settings(environment="test", use_in_memory_store=True) and InMemoryStore. Lifespan selects InMemorySaver. ASGITransport calls the app in-process. Tool unit tests invoke pure-ish helpers directly. This is fast and focused, but it exercises a materially simpler runtime than Compose.

What not to claim

No full-stack integration

No test boots MongoDB, Loki, Prometheus, Redis, PostgreSQL, browser, or both sample services.

No approved-path assertion

The suite does not verify recovery HTTP calls, execution error reporting, or post-recovery signals.

No concurrency/restart assertion

Decision races, SSE backpressure/replay, task recovery, multiple replicas, and checkpoint recovery after process death are untested.

Little frontend behavior coverage

Routes, polling, streaming, decision submission, and report rendering lack browser-level tests.

Which claim does the current suite not prove?

Teach it back

Give a two-minute testing assessment: strengths, seams, and the first three tests you would add.

Model answer
The suite is fast and proves the deterministic core, rejection safety, API basics, helper logic, and two accessibility details through injected memory adapters. It does not validate the real distributed stack. I would first add an atomic concurrent-Approval test, an approved remediation plus verification test against fake HTTP transports, and a Compose/browser test covering SSE reconnect and final Report.
