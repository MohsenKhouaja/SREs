Operator journey

Each stage gets its own route

/simulate chooses a controlled failure. /investigation/[id] shows live Agents and Findings. /approvals/[id] isolates the risky decision and Evidence. /investigation/[id]/report presents the durable outcome. List pages cover Investigations and Approvals; Settings changes the optional provider.

Two synchronization channels

SWR polling

Lists every 3–4 seconds; detail and Approval every 2.5 seconds. It retrieves durable aggregate state and recovers after missed events or refresh.

EventSource SSE

One stream per Investigation. It appends up to 200 recent browser events and gives immediate Agent-step feedback.

The Investigation page deliberately uses both. SSE events supply the activity feed; polled detail supplies authoritative statuses, Findings, Approvals, and Report availability.

Data boundary

TypeScript mirrors API shapes but does not validate runtime JSON

types.ts defines Finding, AgentState, Approval, Report, Investigation, and StreamEvent. apiFetch<T> asserts the decoded JSON type; it does not validate server data. Failed HTTP responses try to surface detail.

The Approval page groups logs, metrics, events, and hypotheses. It queues a decision, waits briefly, revalidates, and navigates back. Those timers hide eventual backend progress but are not a delivery guarantee.

Why it looks this way

The UI follows the product’s evidence-first narrative

PRODUCT.md asks for calm, decision-led screens rather than an AI chat. The implementation uses readable status text, separate stages, explicit Evidence groups, and restrained actions. Component tests verify that status is not color-only and empty states teach the next action.

Frontend limitation

The activity feed uses only current-browser SSE history. After refresh, stored Agent steps exist in API records, but the page does not rebuild the feed from them.

Which channel reconstructs authoritative Investigation detail?

Teach it back

Defend using both polling and SSE, then name their duplication cost.

Model answer
SSE gives low-latency activity, while polling reconstructs durable aggregate state and heals missed live events. The cost is duplicate network traffic, two synchronization models, and possible temporary disagreement. Here that trade favors a responsive demo with a reliable Store-backed view.
