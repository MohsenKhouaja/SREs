Interview question bank

Thirty project-specific prompts. Answer aloud, then use the hint only to audit omissions.

RuleClaim → code evidence → trade-off. Never answer with framework slogans.

System narrative

Walk me through one Investigation end to end.

Hit: failure toggle, durable creation, background graph, fan-out/join, Approval interrupt, branch, Report, SSE.

Why does the start route return 202?

The request accepts long-running work; completion arrives later through records/polling/events.

Where is the system boundary?

Control plane investigates a bundled, controlled lab; no arbitrary host or Docker control.

Why are there nine services?

Separate UX/API/persistence, observability, sample dependencies, and two instrumented services.

Agents and orchestration

What makes an Agent an Agent here?

A specialist graph node with narrow state/tool responsibility—not an autonomous chatbot.

How does fan-out and join work?

Three START edges run collectors; a multi-source edge gates Correlation until all finish.

Why do list fields use reducers?

Parallel partial updates append rather than overwrite sibling Findings and steps.

What does RetryPolicy actually retry?

Thrown node exceptions; tool wrappers usually catch failures and return error envelopes instead.

Could this be a conventional workflow?

Yes; explain why explicit state, checkpoints, branches, and observability still fit graph orchestration.

Evidence and AI

Is the root cause really AI-generated?

Not necessarily. Deterministic profiles and heuristic tools work without a key; the LLM refines one sentence.

Which evidence is real and which is synthetic?

Loki/Prometheus query generated telemetry; Event Agent creates a two-event in-process timeline.

How are hypotheses ranked?

Textual term overlap with serialized evidence, starting at .35 and adding .16 per match.

What happens when Loki is unavailable?

The tool returns structured error data; the collector still creates a profile-worded Finding.

What can the LLM change?

Only root-cause wording; not graph topology, approval, targets, payloads, or execution.

Safety and state

Why is the interrupt node pure?

Resume re-enters the node; placing writes/actions afterward avoids duplicate side effects on replay.

How do you prove rejection cannot remediate?

Conditional edge routes rejected to rejected; only approved reaches execute.

Why are Store and checkpointer separate?

Product query model versus graph continuation state; each serves a different consumer.

Is SSE the source of truth?

No. It is process-local immediacy; GET endpoints reconstruct from Store records.

What survives a backend restart?

Mongo records/checkpoints and named-volume telemetry; tasks and EventHub memory do not.

API and frontend

Why use polling and SSE together?

Polling refreshes durable aggregate state; SSE gives low-latency activity events.

How are dependencies injected for tests?

create_app accepts Settings and Store; lifespan selects in-memory checkpointing.

How are secrets handled?

POST accepts a key into process memory; responses expose only a configured boolean, not the value.

How does the UI reflect product stages?

Separate Simulate, Investigation, Approval, and Report routes preserve one narrative.

Testing and critique

What does the workflow test prove?

Fan-out completion, pending Approval, checkpoint resume, rejection terminal state, and no need for external services.

What important behavior is untested?

Real Compose integration, SSE replay/disconnects, concurrent decisions, approved remediation, restart recovery, model providers.

Name the highest-risk race.

Two decision requests can both observe pending before asynchronous resume persists the first decision.

What would break at multiple backend replicas?

Process-local tasks/EventHub and uncoordinated duplicate checks; clients may connect to another replica.

What is misleading about completed remediation?

Execution errors are captured, but Report still marks the Investigation completed without post-action verification.

What would you improve first?

Auth and atomic decision claiming, durable job recovery, verified remediation, evidence validity, then scalable event delivery.

How would you productionize safely?

Keep human policy, add identity/RBAC/audit, idempotency, leases, durable queues, bounded events, verification, and real integrations.
