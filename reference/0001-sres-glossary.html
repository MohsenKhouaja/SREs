Project glossary

The words below mean exactly what they mean inside this repository. Use them consistently when reading code or answering interview questions.

Primary source CONTEXT.md
supplemented by the state and workflow code
Incident
The observable disruption that needs investigation. In this lab, an Incident is deliberately created by one controlled Scenario.PRODUCT / CONTEXT
Scenario
One of three controlled infrastructure failures: redis-unavailable, database-blocking, or release-regression. The selected scenario activates the lab fault but is withheld from analysis prompts.workflow.py · SCENARIOS
Investigation
One traceable execution identified by incident_id. It owns agent records, approvals, status, checkpoint thread, and final report.models.py · IncidentState
Agent
A named specialist node in the workflow: Log, Metrics, Event, Correlation, or Report. Here, an agent is an application function with a narrow responsibility—not an independent chatbot.workflow.py · _build_graph
Finding
A timestamped observation with a source, human-readable message, and raw tool response. Findings are the smallest durable evidence unit shown by the UI.models.py · Finding
Evidence
The combined Log, Metrics, and Event Findings used by Correlation to rank hypotheses and propose a Root Cause and Remediation.workflow.py · _correlation_agent
Root Cause
The explanation judged to best fit the Evidence. The Groq correlation agent generates competing hypotheses and cites Finding IDs; unavailable model or evidence fails the analysis instead of substituting a diagnosis.workflow.py · _correlation_agent
Remediation
An approved state-changing request to the private lab controller. It can start the observed Redis container, terminate an observed PostgreSQL blocker, or replace an observed v2 container with the prepared v1 image.workflow.py · _execute_remediation
Approval
The operator's explicit approve-or-reject decision. The graph pauses before this decision and the remediation node is unreachable on rejection.workflow.py · _approval_node
Report
The final durable Investigation account: summary, Root Cause, Evidence, recommendation, affected services, and ordered timeline.models.py · ReportJSON
IncidentState
The typed working document passed between graph nodes. Each node returns only its updates; reducers append parallel list updates instead of overwriting them.models.py · IncidentState
Node
One function registered as a graph step. Edges constrain which node can run next; the graph therefore encodes the safety policy as executable control flow.workflow.py · _build_graph
Checkpoint
A saved graph execution position and state, keyed here by the Investigation ID as thread_id. It lets approval resume the same paused run.workflow.py · _config / resume
SSE stream
A one-way HTTP stream from backend to browser. SREs uses it for immediate activity updates while normal GET requests still retrieve durable Investigation state.main.py · stream
